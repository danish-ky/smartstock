SmartStock Product Images Upgrade — installation guide
====================================================

Purpose
-------
One optional image per product; upload/replace/remove for Admin and Manager; image thumbnails in Products, Inventory, Dashboard and Customer Catalog; JPG/PNG/WebP files up to 3 MB, max 4096x4096 pixels. Existing products without images use a fallback.

Prerequisites
-------------
Your existing SmartStock project has the 5-feature upgrade and Customer Read-Only Portal installed, and inventory migration 0003_customer_account is applied. This incremental patch does NOT replace your working project, and does NOT contain any passwords or database data.

Step 1 — Backup
----------------
Ensure your previously made project and PostgreSQL backups are safe. If the project has changed since your last backup, make a fresh folder backup before continuing.

Step 2 — Copy patch and validate (SAFE, no changes)
---------------------------------------------------
Extract this ZIP. Copy SmartStock_Product_Images_Compatible.patch into:
D:\Inventory_Management\smartstock_web

Run in PowerShell:
cd D:\Inventory_Management\smartstock_web
git apply --check --ignore-space-change .\SmartStock_Product_Images_Compatible.patch

If you see any error, STOP and share it. Do not force the patch.

Step 3 — Apply patch
---------------------
git apply --ignore-space-change .\SmartStock_Product_Images_Compatible.patch

git status --short

Step 4 — Backend package and migration
---------------------------------------
cd D:\Inventory_Management\smartstock_web\backend
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python manage.py makemigrations --check --dry-run
python manage.py showmigrations inventory
python manage.py sqlmigrate inventory 0004
python manage.py migrate
python manage.py test

The new migration adds a nullable image field to the inventory_product table. No existing records should be deleted or overwritten. The previous 28-test suite is supplemented with four tests for image permissions/validation. Do not claim the new tests passed unless you see OK on your computer.

Step 5 — Frontend build and run
--------------------------------
cd D:\Inventory_Management\smartstock_web\frontend
npm.cmd run build
npm.cmd run dev

Start Django in a separate terminal:
cd D:\Inventory_Management\smartstock_web\backend
.\.venv\Scripts\Activate.ps1
python manage.py runserver

Step 6 — Manual verification
-----------------------------
- Login as Manager, visit Products, edit one product, upload a JPG/PNG/WebP image, Save.
- Refresh Products: thumbnail persists.
- Visit Inventory, Dashboard and the Customer product catalog; thumbnail should appear where that product is shown.
- Login as Staff or Customer: image upload/delete must be forbidden (HTTP 403), but catalog browsing should still work.
- Login as Manager, edit product and Remove current image, Save; fallback avatar should return.
- Check barcode labels, stock transactions, orders, invoices and payments still work.

Image storage / deployment note
--------------------------------
Local DEBUG=True serves files from backend/media/ through Django; these uploaded files are excluded from Git.
When deploying, configure a persistent media store (e.g. S3/compatible object storage or a persistent volume) and a safe public media URL. Gunicorn/WhiteNoise alone does not persist user uploads, and ephemeral hosting filesystems can lose images after restarts. Do not enable DEBUG=True in production.

Known validation restrictions: JPG/PNG/WebP only; max 3 MB; max 4096x4096 pixels. This is a basic assessment implementation. Public media are NOT private; do not upload confidential product photos. Existing account permissions are enforced server-side on upload and deletion.
